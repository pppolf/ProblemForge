# 检索题目与任务历史

题目页在服务器按名称、标签片段和负责人名称检索，勾选「包含已归档」可扩大范围。结果按创建时间从新到旧分页，最近修改时间另外显示。点击搜索后，条件与当前页写入地址，刷新仍停留在该页。

任务中心默认显示自己发起且当前仍有权限的任务。可按状态、用途、起止时间筛选；填写题目 ID 查看本题团队历史，TeX 也可填写比赛 ID 查看比赛资料构建。题目和比赛筛选不能同时使用。日期输入使用浏览器本地时区，发送到服务器时转为 UTC。

「更早任务」继续翻页，「上一页」返回本次浏览中的前一页；直接打开保存的历史地址或刷新后可继续向后，也可「最新一页」重开查询。页面地址也保留当前选中的任务；打开记录后读取受保护的日志、Judge 报告或 PDF。依赖是否过期以详情中的当前校验为准，列表只展示摘要。

题目工作区保留最近 50 条任务摘要，顶部的「全部 TeX 历史 / 全部 Judge 历史」进入对应对象的完整查询。原列表接口保持兼容，新增分页接口为 `/api/builds/page`、`/api/test-runs/page` 和 `/api/problems/page`。比赛可在任务中心按 ID 查看完整构建历史；现有比赛编排及修订选择流程沿用原入口。

分页按不可变的 `createdAt, id` 降序游标推进，并固定首次查询的时间上界。新插入的任务只触发提示，不会挤动当前页或替换已选历史记录。实时订阅额外关注本页和所选记录，即使它们已超过最近 50 条，仍能更新状态。断线后按原位置回查。筛选输入不会被实时事件或单纯的分页刷新覆盖。

游标绑定当前用户、集合和筛选条件，不能用于改变访问权限。每次请求重新检查对象权限，翻译成员仍只看到授权语言的构建；撤销权限后，旧地址、日志和产物访问也失效。单次请求最多扫描 500 个候选任务；若旧记录大量失去权限，可能出现较短或空页并提供继续游标。这是有界扫描，不等于“后面没有记录”。状态筛选使用查询时的当前状态，分页不冻结整个数据库或历史权限。

显式验证 `pnpm verify:p6:history` 会创建并保留独立 `problemforge_p61_verify_*` 数据库，使用注明未执行的终态元数据验证分页、筛选、权限和 SSE，不投递队列或执行作者代码。默认快查范围不变。
