# 账号与会话

系统管理员在「用户管理」创建、编辑、启停账号和调整系统角色。题目、比赛成员权限仍独立控制。账号编辑使用版本检查，冲突时不会覆盖他人的变更。系统始终保留至少一个未停用、无需重置密码的管理员；并发操作也遵守此规则。

用户在「账户设置」修改密码、查看有效会话、退出其他设备或所有设备。修改密码须验证当前密码，新密码至少 12 个字符，成功后包括当前设备在内的所有会话失效。

管理员发起密码重置后：

1. 该账号所有会话撤销，旧密码暂停登录。
2. 页面只展示此次生成的链接；请通过团队可信渠道转交对应用户。应用不发送邮件，不开放自行注册。
3. 链接 30 分钟有效，仅能使用一次；重新发起会替换旧链接，过期后由管理员重新发起。
4. 用户打开链接、设置新密码后，返回登录页登录。刷新重置页会清除内存中的凭据，需重新打开原完整链接。

重置凭据仅保存 SHA-256 摘要；链接使用 URL fragment，加载页面不将凭据发送到服务器路径或查询参数。提交时通过 POST body 传递。密码、原始会话令牌和重置凭据不进入审计记录，密码及凭据字段配置日志脱敏。普通用户接口不返回重置凭据。正式部署应使用私网 HTTPS。

更改邮箱、系统角色、启停状态会撤销该用户所有会话和未使用的重置链接；仅改名称保留会话。此前若处于待重置状态，变更后仍须由管理员发起新链接，不能借启用账号恢复旧密码。停用账号必须先启用再发起重置。撤销会话不会改密码，用户可以重新登录。

失效会话的后续请求返回 401；已有 SSE 连接在下一次鉴权（至多约 2 秒，取决于请求处理时间）关闭。已经通过授权并开始处理的业务请求不执行追溯回滚。

账号写操作和新会话签发共用 PostgreSQL 事务锁；密码计算在锁外完成，锁内再次检查当前用户、凭据及操作者会话。用户创建/变更、重置、修改密码和撤销会话均记录业务审计。

显式验证：`pnpm verify:p6:accounts`。命令在当前 PostgreSQL 内创建独立的 `problemforge_p60_verify_*` 数据库，应用已提交迁移并保留验证库，不变更开发管理员；不启动 Judge / TeX，不加入默认快查。需当前数据库用户具有创建数据库权限。验证记录写入忽略的 `.local/verify-p6-accounts.json`。
