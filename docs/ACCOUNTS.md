# 登录与本地权限

工作台有两个独立入口：**超级管理员使用本地邮箱 + 密码**；**普通用户使用协会账号或邮箱 + 官网密码**。两者使用同一套本地权限与会话管理，密码验证相互独立。

## 独立超级管理员

在 [超级管理员登录](http://localhost:5180/login?mode=admin) 输入管理员邮箱与本地密码。无需 APPKEY、网络访问协会官网或绑定 userId。原开发库只保留 `admin-f054@problemforge.local` 一个管理员，原密码未修改；本机原凭据记录在 Git 忽略的 `.local/bootstrap-admin.txt`。

独立账号沿用最高系统角色 ADMIN，要求未绑定协会身份且存在有效 scrypt 密码；普通用户及已绑定协会的管理员不能使用本地登录。不存在、停用、要求重置或密码错误均拒绝，不向协会转发本地凭据。登录限流为 8 次/10 分钟，保留 Origin、HttpOnly / SameSite=Strict 和生产 Secure Cookie。签发会话前在账号事务锁内重新核对状态与密码，避免并发改密或停用绕过。

「账户设置」可填写当前密码及两次新密码；新密码为 12—256 字符，验证后保存 scrypt 哈希并撤销全部会话，需要重新登录。改密有 Origin/CSRF、权限、当前密码与限流检查；不会更改协会账号的密码。数据库和审计均不保存明文密码。

全新部署时，在私有配置或进程环境设置 `PF_ADMIN_PASSWORD`（12—256 字符），再初始化：

```powershell
pnpm admin:init --email 管理员邮箱
```

也可设置 `PF_ADMIN_EMAIL`。初始化不接受 `--user-id`，不覆盖已有用户、身份、权限或密码；完成后可移除初始化密码配置。当前开发库已有管理员，不重复初始化。`pnpm user:link` 明确拒绝将独立超级管理员绑定到协会；同邮箱的协会登录也不能接管该账号。

## 协会登录配置

普通用户的后端认证固定向 `https://www.cwnupaa.com/api/user/external/login` 发送 `appKey`、`loginType: "password"`、`account`、`credential`，成功后建立本系统会话。未接入验证码、短信或普通用户的本地密码回退。

在主目录原 `.env` 中填写：

```dotenv
ASSOCIATION_APP_KEY=
```

2026-10-05 已将用户提供的 APPKEY 填入 Git 忽略的原 `.env`，确认无活动任务后重启原 `pnpm dev`；`/api/auth/config` 已返回 `configured: true`，继续使用 `http://localhost:5180` / API 3100。使用随机不存在的账号做了一次接口连通性检查，收到 `LOGIN_FAILED`，未创建本地用户或会话；这只验证接口可达及失败响应链路，真实账号成功登录由用户在原页面自行测试，尚未确认。密钥只由后端使用，不加 `VITE_` 前缀、不写到前端或 Git。生产 Compose 仅把它传给 API，Worker 和执行沙箱不需要它；云端私有配置仍须单独填写。

官网返回业务 code=200 且用户身份完整才允许登录。请求使用 HTTPS、8 秒超时、不跟随重定向、最多读取 32 KiB 响应；网络失败、异常响应和缺少配置明确报错。账号可去除首尾空白，密码原样转发。密码、APPKEY、远端原始响应不写数据库、业务审计或日志。本地 8 次/10 分钟登录限流、Origin、CSRF、HttpOnly / SameSite=Strict Cookie 继续有效。

## 新用户与旧账号

协会 `userId` 作为精确的十进制字符串保存，兼容 Java Long，避免 JavaScript 数字精度导致身份混淆。同一 userId 使用账号或邮箱登录均对应同一本地用户。首次登录自动建立 **USER 普通用户**；协会接口不提供本系统角色，不能自动取得管理员权限。姓名、账号名和邮箱在后续登录时同步，不使用姓名或邮箱自动合并身份，也不保存学号或真实姓名字段。

2026-10-02 原开发库已清空其他用户、题目和比赛，保留独立超级管理员、模板和编译配置。若其他部署仍有历史普通用户需要继承本地权限，操作者先核对协会 **userId（不是学号、账号名或邮箱）**，再显式绑定；此命令不用于独立超级管理员：

```powershell
pnpm user:link --email 历史普通用户邮箱 --user-id 协会userId
```

绑定保留原本地用户 ID、角色和成员关系，清除其旧本地密码与重置凭据并撤销旧会话。已经绑定其他身份或该协会 ID 已被另一个本地用户使用时拒绝覆盖/合并。普通旧账号邮箱冲突返回 ACCOUNT_LINK_REQUIRED；独立管理员邮箱冲突返回 LOCAL_ADMIN_ACCOUNT，引导使用本地入口。2026-10-02 接入时没有真实 APPKEY 或身份 ID，没有绑定任何账号；2026-10-05 仅补入 APPKEY，未执行账号绑定。

## 权限与会话

「用户管理」显示独立本地账号与协会身份，调整本系统角色、启停和撤销会话。协会用户的名称、邮箱、密码及注册在官网管理；独立超级管理员在账户设置修改本地密码。本地普通用户创建、通用改密与一次性密码重置接口保持关闭，旧密码重置 URL 回到登录页。

账号权限更新使用版本检查。角色或启停改变会撤销全部本地会话；本地停用用户即使协会验证成功也不能登录。最后一个可登录的独立超级管理员不能被停用或降权，即使还存在协会管理员也一样。登录签发会话、改密、管理员变更与显式绑定共用 PostgreSQL 事务锁，避免停用或权限修改与会话签发交错。

用户可以在「账户设置」查看有效会话、退出其他设备或所有设备。有效期仍为 7 天；失效会话后续请求返回 401，SSE 下一次鉴权时关闭。官网文档没有提供令牌验证/退出通知接口，官网改密、停用或退出不会主动撤销已经签发的本地会话；需要立即停止本系统访问时在此停用或撤销会话。

## 定向验证

`pnpm verify:access` 使用模拟的协会响应和**原数据库的必定回滚事务**验证实际 Fastify 路由、独立管理员登录/改密、最后管理员保护、协会身份隔离、会话/权限与直接冻结。不开新端口、不建数据库、不发送外网请求、不执行作者代码或 TeX。默认 `test` / `test:quick` 不变。

P0—P7 的本地密码账号验证脚本属于历史验收路径，未对新登录重新验收，不能直接拿旧夹具向协会登录。当前 APPKEY 已配置、接口连通性已检查；真实账号成功登录等待用户在原 5180 页面测试，目标云主机的登录与 HTTPS 会话尚未验收。
