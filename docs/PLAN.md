- 等原任务结束后，停止确认属于 f054 的 API、Vite、TeX Worker、Judge Worker；不能让不同目录/不同版本的 Worker 误消费同一队列。保留历史数据库、产物和凭据，按需将配套私有文件迁入主目录的独立本地目录，校验哈希并更新配置。
- 执行 `pnpm install --frozen-lockfile`、`pnpm db:generate`；核对目标数据库迁移状态后只应用待执行迁移。启动主目录开发服务，沿用本项目的独立 Linux 沙箱。
- **完成条件：**主目录服务可登录、可读取现有 P2 报告和最新样例 PDF，确认进程实际加载主目录源码。迁移配置不需要重跑完整 P2；发现具体回归再定向检查。

### P3.1 有预算的对拍、反例与复现 [ ]

- 保存有版本与 CAS 冲突保护的对拍配置：生成器、参考解、被测解、Checker、argv、起始种子、迭代上限、总预算及停止策略。任务固定程序/profile/判题配置/Validator 的具体版本及哈希，复用数据库任务清单、幂等提交、取消、私有输出和按目的失效机制。
- 真实执行生成 → Validator/适用额外 Validator → 参考解 → 被测解 → Checker。多解题依 Checker 判定；参考解、生成器或工具失败不能算作被测解的反例。报告区分发现反例、迭代完成、预算耗尽、取消和工具/基础设施错误；显示已完成次数与实际种子。
- 反例持久保存原始输入、参考/被测输出、源码和 profile 版本、参数、种子、判定及日志。复现优先使用保存的输入字节和原执行快照；重新生成仅作确定性检查，不能覆盖原反例。显式加入正式数据时鉴权、检查编号/重复与相关依赖，产生新的 TestCaseRevision，保留来源并使相关验收过期。
- 工作区增加对拍配置、启动/取消、反例详情、复现和显式入库；支持刷新后继续查看，历史结果与当前有效结果有明确标识。复用 `judge-snapshot.ts`、`test-runs.ts`、Judge Worker / Executor 和 JudgeWorkspace 的现有边界，按职责拆分新模块。
- **定向验收：**用现有小型生成器/正确解/错误解找到一个反例，按保存输入复现同一判定并显式入库；另验证运行中取消保留已有证据且释放执行资源。增加一个有关的权限拒绝或依赖过期检查，避免扩展成大量组合。

### P3.2 真实交互执行与有界通信记录 [ ]

- 先核对固定 go-judge v1.8.5 与 testlib 源码/协议，扩展当前仅发送单个 command 的 `packages/judge-adapter`，在 Linux 沙箱内建立选手程序与 Interactor 的真实双向管道。隐藏输入只交给 Interactor，双方 stderr 与工作文件各自隔离。
- 明确支持“Interactor 直接判定”和“Interactor 输出交 Checker 判定”两种模式，版本化所选工具与配置，保存双方 Invocation。不能仅解除 API 对 INTERACTIVE 的拒绝而继续走批处理执行器。
- 限制双方 CPU、内存、进程、输出及总墙钟、空闲等待；记录带方向、顺序和截断标记的有界通信内容，并按当前题目权限下载。查询次数由 Interactor 的协议执行，不用 stdout 行数代替。
- 正确处理 EOF、未 flush、超限和提前退出，区分选手错误、Interactor/Checker 故障和基础设施失败。Interactor 已作出有效判错时，平台清理对端产生的终止状态不能覆盖原判定；取消必须终止并回收双方。
- **定向验收：**一题完成正常交互、有效判错、未 flush/空闲超时及取消，确认对端释放、隐藏输入隔离与有界记录授权。若协议能力确有不足，记录具体阻塞并继续 P3.3，禁止宿主机执行回退。

### P3.3 数据组、额外校验、依赖 DAG 与评分 [ ]

- 将现有 `groupName` 标签升级为有版本的数据组配置，固定成员数据版本、组分数、聚合方式、依赖组和组级额外 Validator。保留已有主 Validator / 全局 EXTRA_VALIDATOR 能力，补齐组级适用范围和来源快照；已有分组标签须明确迁移或由用户确认映射。
- 组依赖校验同题引用、存在性、自环和环路，保存时拒绝非法 DAG。明确无数据组、停用数据、成员/依赖变更语义，避免静默计分；配置变化按依赖使原验收失效。
- 明确 ACM 为全部必需数据 AC；部分分至少支持整组全过得分和按显式测试权重累计，写清分母、满分和舍入。默认依赖组未全过时本组计零并显示阻塞原因，总分为各组得分之和，使用整数或定点计算。
- 报告同时展示测试判定、组内原始得分、依赖后的组得分与总分。扩展解法的组/总分预期声明，正确解要求满分，错误解按声明判定或分数范围验收；CE、工具与基础设施错误不能充当预期命中。
- **定向验收：**一个可手算的 20/30/50 分组配置验证组内聚合和依赖阻断，再确认一个环路拒绝、一个组级额外 Validator 拒绝及配置改变后旧结果失效。
