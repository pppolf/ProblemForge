# ProblemForge 详细使用说明

本说明面向本机手动测试，入口和已有数据于 **2026-10-01** 核对。网页侧栏「使用指引」提供流程简版。首次使用可先看第 1—3 节，再按第 4—7 节完成自己的题目和比赛。

## 1. 当前测试环境与登录

### 1.1 使用哪个地址

**请使用 [http://localhost:5183](http://localhost:5183)。** 当前已经启动，打开浏览器即可测试。

| 项目 | 当前值 |
| --- | --- |
| 应用版本 | `p71-20261001-r2`，代码提交 `0537583` |
| Compose project | `problemforge-p7-upgrade` |
| 启动配置 | `D:\project\ProblemForge\.local\p7-upgrade.env` |

打开本机文件 **`D:\project\ProblemForge\.local\manual-test-access.txt`**，里面有可直接复制的邮箱和密码：

| 账号 | 用途 | 原始凭据位置 |

第一次建议用「部署演练出题人」。若要用自己的账号，管理员先在「用户管理」创建普通用户，再由示例题负责人通过「成员与权限」授权；新用户默认不会看到别人的私有题目。

### 1.3 启动、停止和查看状态

以下命令在 PowerShell 中执行。先打开 Docker Desktop，确保 Linux 引擎运行，然后进入项目目录：

```powershell
Set-Location D:\project\ProblemForge
```

重新启动已有实例：

```powershell
pnpm ops up --env .local/p7-upgrade.env
```

命令使用现有镜像和数据卷。初始化任务成功后，`migrate` / `storage-init` 显示 `Exited (0)` 是正常现象，不需要重复初始化管理员或导入数据。

查看容器：

```powershell
docker compose --env-file .local/p7-upgrade.env -f infra/compose.prod.yml ps
```

测试结束后，先确认任务中心没有排队/运行任务，再停止本套环境：

```powershell
docker compose --env-file .local/p7-upgrade.env -f infra/compose.prod.yml stop
```

查看最近日志：

```powershell
docker compose --env-file .local/p7-upgrade.env -f infra/compose.prod.yml logs --tail 100 api tex-worker judge-worker
```

日常停机用 `stop` 即可。`down -v` 会删除命名卷中的数据库与私有文件，不用于本次测试的日常清理。

## 2. 页面和角色分工

侧栏「题目」管理单题，「比赛」组合已冻结题目，「任务中心」查询历史构建和 Judge 任务，「账户设置」修改密码和管理登录设备。

| 单题工作区 | 主要操作 |
| --- | --- |
| 题面与双题解出版 | 按语言分别写题面、文档题解、Beamer，选模板、绑定样例、构建和查看 PDF |
| 程序、数据与验收 | 程序、测试数据/生成计划、工具自测、验收与日志、数据组与评分、对拍与反例、判题配置 |
| 组织、修订与协作 | 名称/标签/负责出题人、复制、归档、修订审核、题包导出、成员授权 |

系统角色与题目/比赛的成员角色分开控制：

| 成员角色 | 日常职责 |
| --- | --- |
| 负责人 `OWNER` | 编辑、授权、审核、冻结、发布和撤回 |
| 编辑 `EDITOR` | 编写稿件/程序/数据、建立修订、提交审核 |
| 审题 `REVIEWER` | 查看固定修订、评论、批准或要求修改 |
| 只读 `VIEWER` | 查看有权访问的内容和结果 |
| 限定语言翻译 `TRANSLATOR` | 仅处理授权语言的正文与内容信息，不能查看程序、私有测试或 Judge 日志；比赛无此角色 |

「负责出题人」是组织字段；让某人实际访问题目时，仍需在「成员与权限」保存授权。比赛成员能访问比赛固定材料，不会因此获得源题编辑权限。

- [部署演练 · A](http://localhost:5183/problems/cmuowveue001cnq07c1py7vb6)
- [部署演练 · B](http://localhost:5183/problems/cmuowvkr5003rnq07uedw5sem)
- [部署演练 · C](http://localhost:5183/problems/cmuowvqnv005unq073dmt6zti)

1. 打开 A/B/C 示例，在出版区切换题面、文档题解和 Beamer，观察三个独立稿件及模板绑定。
2. 进入「程序、数据与验收 → 验收与日志」，选已有完整验收，查看矩阵、输入/答案、编译和执行日志。无需为了查看历史重新运行任务。

5. 准备修改时，回到题目「概览与组织」，先保存未完成编辑，再点击「复制为我的私有题目」。在副本中修改名称、标签和各稿件标题。
6. 副本改完后重新验收、审核和冻结。它不会继承源题的旧成功任务和审核凭证。

## 4. 编写三类文稿

### 4.1 创建、选择模板和保存

1. 在题目列表点击「＋ 创建题目」，输入名称，点击「创建并编辑」。默认建立 `zh-CN` 的三份独立文稿。
2. 在「题面与双题解出版」选择语言和稿件类型。
3. 选择已发布模板。本实例当前可用：题面 `部署演练 · statement-compact` v1；文档题解 `部署演练 · editorial-document-blue` v1；Beamer `部署演练 · editorial-beamer-wide` v1。
4. 填写当前稿件的标题、作者和正文，确认「已启用」，点击「保存」，看到「已保存 vN」后再继续。
5. 三类稿件分别操作。「停用」保留正文。需要英文稿时输入 `en` 并点击「添加语言」，再分别填写三种英文稿。

题目列表名称与各稿件标题分别维护，需要时分别修改。普通作者填写正文，文档外壳、宏包、字体和主题由管理员模板提供。

### 4.2 可直接粘贴的 A+B 文稿

只复制代码框内的正文，不加入 Markdown 代码框标记。

题面：

```tex
给定两个整数 $a$ 和 $b$，请计算它们的和。

\InputFile
输入一行，包含两个整数 $a$ 和 $b$，满足 $0 \le a,b \le 10^9$。

\OutputFile
输出一个整数，表示 $a+b$。

\Note
请注意整数范围。
```

文档题解：

```tex
\section{思路}
读入两个整数，计算并输出它们的和。

\section{复杂度}
时间复杂度为 $O(1)$，额外空间复杂度为 $O(1)$。
```

Beamer：

```tex
\begin{frame}{A+B：解题思路}
\begin{itemize}
\item 读入整数 $a$ 和 $b$。
\item 使用足够范围的整数类型计算 $a+b$。
\item 输出结果，时间复杂度为 $O(1)$。
\end{itemize}
\end{frame}
```

题面样例从正式数据绑定：在测试数据中勾选「题面样例」，保存输入和答案后，在题面「引用样例的具体数据版本」中选择它，再保存。数据更新后已有绑定仍指向旧版本，需显式重新选择。

图片通过「图片资源 → 上传图片」上传 PNG/JPEG，再「插入当前稿件」。不要填磁盘路径；正文不要加入 `\documentclass`、`\usepackage`、`\begin{document}` 或文件读取命令，样式需求交管理员模板处理。

### 4.3 构建和预览

点击当前稿件「构建 PDF」，等待 `QUEUED → RUNNING → SUCCEEDED`，查看「PDF 预览」；失败切到「构建日志」。三类稿件各自构建。

正文、样例或模板绑定改变后，旧 PDF 仍可查看，但会提示历史/过期；重新点击「构建 PDF」才能检查新版本。「重试此任务」沿用原任务快照。私有预览和下载足以完成普通自测，公开链接的含义见第 8 节。

## 5. 从零完成 A+B 的 Judge 验收

这是供你手动执行的最小练习。本次容器清理没有替你创建或运行这些新任务。

### 5.1 判题配置

创建题目「我的测试 · A+B」，进入「程序、数据与验收 → 判题配置」，设置并保存：

| 配置 | 值 |
| --- | --- |
| 执行方式 | 批处理 |
| 评分模式 | ACM：全部必需数据 AC |
| Checker 模式 | token（忽略 ASCII 空白，拒绝多余 token） |
| I/O | 标准输入输出 |
| 时间 / 内存 | 1000 ms / 256 MiB |

此练习不需要自定义 Checker 或 Interactor，保持数据组为空，不启用生成计划。

### 5.2 主标程

在「程序」点击「新建程序」，名称「A+B 主标程」，角色「主标程」，profile `GNU C++17`，启用，预期 `AC`：

```cpp
#include <iostream>
using namespace std;
int main() {
    long long a, b;
    cin >> a >> b;
    cout << a + b << '\n';
    return 0;
}
```

点击「保存程序」，再「编译当前源码」检查日志，返回「程序」继续添加工具。

### 5.3 Validator

新建名称「A+B 输入校验」，角色 **Validator**，profile `GNU C++17`，启用：

```cpp
#include "testlib.h"
int main(int argc, char* argv[]) {
    registerValidation(argc, argv);
    inf.readInt(0, 1000000000, "a");
    inf.readSpace();
    inf.readInt(0, 1000000000, "b");
    inf.readEoln();
    inf.readEof();
}
```

保存。`testlib.h` 由平台工具链提供。这个校验器要求两个数间恰好一个空格，并以换行结束；填写输入数据时在数字后按一次 Enter。

### 5.4 错误解

新建名称「故意做减法」，角色「错误解」，profile `GNU C++17`，启用，预期判定选 `WA`：

```cpp
#include <iostream>
using namespace std;
int main() {
    long long a, b;
    cin >> a >> b;
    cout << a - b << '\n';
    return 0;
}
```

保存。错误解用于检查数据能否发现已知错误；符合预期的 WA 可以使整体验收通过。编译失败不能当作有效 WA。

### 5.5 正式数据

进入「测试数据 / 生成计划 → 添加数据」，逐条填写，勾选「保存指定答案（也可由主标程生成）」后填写答案，再「保存版本」。输入与答案末尾都加换行，三条均启用：

| 编号 | 输入第一行 | 答案第一行 | 题面样例 | 分组标签 |
| --- | --- | --- | --- | --- |
| 1 | `1 2` | `3` | 是 | `main` |
| 2 | `0 0` | `0` | 否 | `main` |
| 3 | `1000000000 1000000000` | `2000000000` | 否 | `main` |

`main` 只是整理标签，不自动建立计分组。答案可直接填写，也可先保存无答案数据，再由主标程生成。

批量上传使用「导入 ZIP」，成员形式为 `1.in` / `1.ans` 或 `tests/1.in` / `tests/1.ans`。答案可缺省；同编号冲突整批拒绝。单个输入/答案最大 1 MiB；测试 ZIP 最多 100 组、压缩输入 8 MB、展开内容 16 MB。

### 5.6 自测、答案和验收

可先在「工具自测 → 添加自测」为上述 Validator 保存合法输入 `1 2` 加换行，预期 `ACCEPT`；再保存非法输入 `-1 2` 加换行，预期 `REJECT`。点击「运行自测」核对结果。非法输入放在自测里，不加入启用正式数据。

然后进入「验收与日志」：

1. 点击「校验输入」，确认启用正式数据通过 Validator。
2. 如需生成/更新答案，点击「生成答案」。完成后打开报告「输入与答案」，选择数据并点击「收集所选输入 / 答案到正式数据」。收集产生新正式版本；仅生成任务不会改写正式数据。
3. 回题面选择 #1 当前含答案的样例版本，保存三份文稿，按需构建 PDF。
4. 确认程序、判题配置、数据已保存，点击「验收当前版本」。
5. 检查「验收矩阵」：主标程全部 AC；减法错误解在 #1、#3 为 WA，在 #2 可以 AC。
6. 检查总体验收通过。**`SUCCEEDED` 仅表示任务执行完成，还要看验收结论。**

修改程序、数据或判题依赖后旧报告可能过期，需点击「验收当前版本」。只改文稿通常不使 Judge 报告失效，但会影响文稿构建及修订审核。

## 6. 整题修订、审核与冻结

各编辑器的「保存」保存自身版本；整题修订把所有已保存内容固定成可审阅清单。

1. 完成验收，检查各分区没有未保存编辑，进入「组织、修订与协作 → 修订与审核」。
2. 确认「当前判题依赖已验收」，填写修订说明，如「首次手测完整版本」。
3. 点击「保存当前工作副本为修订」，选中新修订，检查与当前工作副本的差异。
4. 点击「提交审核」。审题人检查稿件、固定程序/数据和验收报告，评论后选择「批准本修订」或「要求修改」。
5. 负责人在批准后点击「检查验收并冻结」，得到「已冻结」状态。

单人手测时负责人可以自行提交并批准；团队协作可给第二个账号「审题」角色。

冻结需要工作副本与修订一致、匹配的成功验收，以及至少一种启用且非空题面。修改依赖后要保存新修订，不能沿用过期审核。工作副本继续编辑不会改变历史冻结清单。

「恢复为新修订」追加新的工作版本并保留历史，恢复后重新验收。「归档」保留历史与产物，列表默认隐藏，可勾选「包含已归档」找到。

## 7. 编排比赛和生成资料

1. 在「比赛」创建比赛，进入「比赛编排」，填写名称、署名、语言、场次、页眉日期和封面日期。
2. 分别选择题面、文档题解和 Beamer 的比赛模板；本实例三套已发布模板均支持比赛。
3. 选择有权访问的源题及其「已审核冻结的修订」，点击「加入比赛」。初次可只加入自己的 A+B。
4. 设置题号，用「上移/下移」控制题册顺序，「Beamer 讲解顺序」独立控制讲解次序，重排仍保留原题号。
5. 点击「保存编排」，检查材料完整性，负责人点击「检查完整性并冻结」。
6. 在「冻结与资料」选择冻结版本，分别生成三类资料，或「同时生成两种题解」。
7. 选择子任务查看「PDF 预览」「真实编译日志」「固定来源」。组合任务部分失败时可只重试失败子任务。

冻结比赛要求选定语言的题面完整，两种题解按需构建。缺稿时，回源题补齐并审核冻结新修订，再更新比赛选择；也可勾选「显式选择题目子集」只构建完整材料。子集 PDF 的来源会明确标示。

## 8. 题包导出、发布与导入

### 8.1 私有导出

进入题目或比赛「题包与发布」，选择固定修订、用途、格式，点击「生成题包」，阅读报告后「下载私有题包」。

| 用途 | 内容 |
| --- | --- |
| 题面 | 正文及引用样例、图片，不含私有正式数据和题解 |
| 文档题解 / Beamer 题解 | 分别交付对应稿件 |
| 正式数据与判题工具 | 数据、答案及判题工具，不含参考解源码 |
| 参考解源码 | 启用主标程和正确解 |
| 完整题目包 `FULL` | 原生格式的完整源码交接与再导入 |

第一次往返测试选择 **ProblemForge 原生 v1 + 完整题目包**。未冻结题目修订可先私有导出，正式发布需要当前工作副本对应的冻结版本。

### 8.2 发布链接

私有下载按当前成员权限检查。「公开发布」生成无需登录的链接，每类 PDF/题包分别发布和撤回，发布题面不会自动发布题解。

当前服务仅监听本机回环，材料发布不会自动把网站部署到公网。普通自测用私有预览/下载即可；测试发布时使用自己的测试材料，在隐私窗口检查，再「撤回」验证后续下载不可用。已下载副本无法追回。

### 8.3 导入

在题目列表点击「导入题包」，选择格式与 ZIP，点击「检查兼容性」。先读报告，再确认「创建私有题目」；历史记录可在「我的历史检查」重开。

原生只有 `FULL` 可恢复为工作副本。新题归导入者私有，需重新验收和审核，不继承成员、审批、发布和旧成功任务。模板版本不匹配时重选本机已发布模板；profile 不匹配时按报告处理映射。

Polygon 为离线明确子集，`BLOCKED` 项必须处理。真实外部样包验收目前暂缓，不把原生往返当成完整 Polygon 兼容。字段和大小限制见 [PACKAGES.md](PACKAGES.md)。

## 9. 进阶判题

### 9.1 生成计划

先保存启用的「生成器」程序，在「测试数据 / 生成计划 → 添加计划」填写生成器、起始编号、数量、种子和 JSON 字符串数组 argv，如 `[]` 或 `["100"]`，保存后「执行生成计划」。argv 不解释 Shell。

种子逐次递增，作为最后一个参数及 `PF_SEED` 传入。结果显式收集后才成为正式数据。若将生成结果用于固定数据组，收集完停用对应生成计划，避免再次生成同编号数据。

### 9.2 数据组和部分分

在「数据组与评分」添加组，或「按现有标签建立草稿」，填写标识、满分、计分方式、成员及依赖，再「保存数据组」。启用正式数据必须恰好被分配一次。

- `ALL`：全组通过才得满分。
- `WEIGHTED`：按通过数据的权重比例计算。
- 依赖：依赖组未全过，本组最终分为零，报告保留原始分和阻断原因。

修改数据后用「成员升级到当前版本」并保存。在「判题配置」选择部分分并保存，不能只填整理标签。主标程/正确解仍需全 AC、满分，其他解法可设置总分或组分预期，报告见「组分与总分」。例如 20/30/50 分三组，第二组通过一半权重，第三组依赖第二组且本身全过，得到 `20+15+0=35` 分。

### 9.3 对拍与反例

选择生成器、参考解、另一个被测解、Checker、argv、种子、迭代上限、总预算和停止策略，保存后运行。首次使用少量迭代和明确预算。

反例可下载输入/参考输出/被测输出、「复现保存输入」，或填写新编号后「显式加入正式数据」。入库使相关验收过期，应重新验收。预算内未发现反例不等于证明正确。

### 9.4 Checker、文件 I/O 和交互

自定义判题先保存启用的 testlib Checker，在配置中选择 `CUSTOM`，用工具自测检查接受/拒绝语义。文件 I/O 配置指定输入/输出文件名，程序相应读写，stdout/stderr 仍单独保留。

交互题保存启用的 Interactor，选择双向交互，设置判定方式、资源和空闲限制，注意 flush、EOF，在报告检查双方执行结果与通信记录。详细协议见 [JUDGE.md](JUDGE.md)。作者程序和 TeX 只由独立 Linux 沙箱执行，不可用时失败，不在 Windows 宿主机回退。

## 10. 历史任务、取消和重试

「任务中心」按 TeX/Judge、状态、用途、题目/比赛 ID 和起止时间筛选。ID 是对象地址最后一段。默认显示自己发起且仍有权限的任务；填写对象 ID 可查询该对象有权查看的团队历史。

「更早任务」向历史翻页，「上一页」返回本次浏览上一页，「最新一页」重开查询。地址保存筛选、当前页和所选任务；实时新任务提示不会替换当前报告/PDF。工作区仅保留最近 50 条摘要，更早记录用「全部 TeX 历史 / 全部 Judge 历史」。

| 状态 | 含义 |
| --- | --- |
| `QUEUED` / `RUNNING` | 等待/执行，可取消；持续堆积时查看运行管理与 Worker 日志 |
| `SUCCEEDED` | 执行完成，Judge 还需看验收是否通过 |
| `FAILED` | 检查错误码、编译/执行日志，区分源码、工具、数据和基础设施问题 |
| `CANCELED` | 已取消，保留已完成证据，可按需重试 |
| 历史 / 过期 | 原结果可读，不能充当当前依赖的有效验收或发布依据 |

「重试原快照」执行当时的版本。更改源码/数据/配置后应提交当前版本新任务。默认每用户最多同时有 3 个 Judge 任务、6 个 TeX 构建排队或运行，不要连续重复点击。更多检索说明见 [HISTORY.md](HISTORY.md)。

## 11. 保存冲突与草稿恢复

文稿、程序、比赛和模板显示保存中、未保存、已保存版本及失败提示。请求发出后继续输入的改动仍为未保存状态。浏览器标签页记住语言、稿件、功能区和程序选择，返回列表保留搜索条件。

**导航记忆不是正文备份。** 刷新/关闭前先保存。遇到失败、409 冲突或登录失效：

1. 保持编辑器，点击「下载本地草稿」。
2. 查看 JSON，下载或复制保存到本地；下载受限时使用「复制」，也可在文本框全选复制。
3. 取回草稿后再登录或重新载入服务器版本。
4. 对照内容和基准版本，逐项粘贴合并后保存。

没有草稿 JSON 自动导入/覆盖按钮。草稿含私有正文/源码，需自行保管；弹窗内容只在浏览器内存里，关窗前实际保存为文件。

冲突保留、复制 JSON 和导航恢复已做浏览器验证。内嵌浏览器的 Blob 下载、401 编辑保留及全部原生离开弹窗组合尚未全部完成浏览器实测，具体限制见 PROGRESS。

## 12. 管理员日常操作

### 12.1 账号

「用户管理」创建、编辑、启停账号并调整系统角色。「账户设置」修改密码、查看会话、退出其他设备。新密码至少 12 个字符。

管理员发起重置后旧密码暂停登录、已有会话撤销，页面提供 30 分钟有效的一次性链接，应用不发送邮件。重新发起使旧链接失效。修改密码会注销包括当前设备在内的全部会话。邮箱、系统角色、启停变更也会撤销会话，仅改名称保留会话。最后一个可用管理员有保护；停用/重置测试建议新建专用普通账号。详见 [ACCOUNTS.md](ACCOUNTS.md)。

### 12.2 模板与编译 profile

管理员在模板中心「复制为新版本」→ 编辑 →「保存草稿」→「验证样稿」→ 检查「真实 PDF 预览」及日志 →「确认预览并发布」。已发布版本不可原地修改。

发布新版不会自动重绑定现有题目/比赛，使用者显式换绑再构建。归档停止新选择，撤回阻止新构建。协议见 [TEMPLATES.md](TEMPLATES.md)。编译配置由管理员维护 C++17/C++20/Python 3、优化及资源限制，任务固定具体版本；配置变化后需核对程序与验收有效性。

### 12.3 运行、容量和备份

「运行与审计」应显示 `p71-20261001-r2`、Git `0537583`、迁移一致、数据库/Redis/Worker/沙箱可用。可查看任务、配额、存储、预留、缓存引用和新增登记量。

重要测试完成后，在无活动任务且编辑已保存时，可做一次本地一致备份，期间应用会短暂停止写入：

```powershell
$backupName = Get-Date -Format 'yyyyMMdd-HHmmss'
pnpm ops backup --env .local/p7-upgrade.env --out ".local/backups/manual-$backupName"
```

这是数据库与私有文件配套的明文备份。加密备份、密钥保管、保留预览、盘点及空实例恢复见 [MAINTENANCE.md](MAINTENANCE.md) 和 [DEPLOYMENT.md](DEPLOYMENT.md)。已有加密备份密钥在 `.local/keys/p71-backup.key`，不随题包导出。

## 13. 常见问题

| 现象 | 处理 |
| --- | --- |
| 旧端口打不开 | 5181/5182/5184/5185/5186 已清理，使用 5183 |
| 5183 打不开 | 检查 Docker Linux 引擎，执行第 1.3 节启动命令和 `ps` |
| 账号不对/掉登录 | 用本机登录说明，固定 `localhost:5183`，不要同浏览器交替登录多个端口 |
| 新用户题目列表为空 | 需要负责人授权，或自己创建私有题目 |
| 模板列表为空 | 检查稿件类型、语言及管理员发布状态 |
| 保存后 PDF 没变 | 保存和构建分开；创建新构建并选择新任务 |
| TeX 拒绝命令 | 按位置提示修正正文，导言、宏包和样式交模板处理 |
| Validator 拒绝 A+B | 检查范围、单空格和行末换行 |
| 任务完成但未通过 | 查看矩阵、预期判定、自测和日志，不能只看 SUCCEEDED |
| 样例列表为空 | 数据要标记样例且当前版本有答案；生成答案后还需显式收集 |
| 生成/答案不能收集 | 检查依赖是否过期，按当前配置新建任务 |
| 数据组版本过期 | 升级成员到当前版本并保存，全部启用数据恰好覆盖一次 |
| 冻结失败 | 检查未保存内容、工作副本差异、有效验收、批准状态及启用题面 |
| 比赛找不到源题修订 | 需要已冻结修订和源题访问权限 |
| 比赛缺稿 | 检查语言/冻结修订/启用状态；补齐并选新修订，或显式选子集 |
| Worker/沙箱不可用 | 查看运行页和容器日志，恢复后提交新任务或重试原快照 |
| 保存冲突 409 | 先导出本地草稿，再载入服务器版本合并 |
| 导入 BLOCKED | 逐项处理兼容报告，不认定为已完整兼容 |

反馈时记录入口、角色、对象 ID、操作步骤、任务 ID、错误码与关键日志；截图不包含密码、会话或密钥。
